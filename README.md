# 研究工作流

用于研究与学习项目的可复用工作流：六个阶段，每阶段三个门槛（材料就绪、独立核验完成、人类授权），预算受控的修正，以及明确的人机分工。支持个人与小组研究。

**开始前只需读两份：本文件和 [人机分工](docs/division-of-labor.md)。**后者规定人和 AI 各自负责什么，与任何其他文档冲突时以它为准。其余文档按需读。

**版本 v0.9.6**；Step 1–6 已校准，具体项目的预算、标准与授权仍须按项目批准。主目录为中文权威版本。[英文参考版](en/README.md)与中文同版本，同步状态见 `translation-manifest.json`。

本仓库提供规范和记录模板，不是可执行的编排服务或实时资源监控器。

## 怎么开始

1. 在 GitHub 点 **Use this template** 建新项目仓库，在能读取项目文件的 agent 环境中打开它。成果留在新仓库，不混进模板。
2. 放入已有资料，或给出可访问的路径／链接。不用手填模板。
3. 粘贴下面的指令。agent 先读材料、判断从哪个阶段进入、提出第一段计划；你批准后才开始实质研究。

```text
请按本项目的 docs/division-of-labor.md、AGENTS.md 和 research-workflow.yaml
初始化研究项目，并读取适用阶段的规范。

我的研究主题／问题：[填写]
目前已有：[宽泛想法／候选问题／已确定问题／已有协议或结果]
希望项目最终带来：[可列多个目标，无需排序；不确定也可以]
已有材料：[文件路径或链接；没有则写无]
已知交付要求、截止日期及限制：[填写；未知可留空]
预算硬上限：[如有请填写；没有则请 agent 提议]

先读已有材料，记录采用的工作流提交版本。按已有成果确定进入阶段，
只补缺失前提，不从头重复。先说明当前环境能支持哪些独立核验、
资源统计、暂停和保存能力。然后提出第一段工作的范围、预期产出、
档位、预算和停止条件，组成一个决策包供我批准。

每段工作开始前告诉我：在做什么、会得到什么、接下来进哪一步、全局在哪。
只对尚未明确的信息一次问一个选择题。初始计划批准前不开展实质研究。
```

agent 只有在获得访问权限并收到明确指令时才会读取文件；单独发一个仓库链接不会触发流程。私有仓库需要连接账户或提供本地副本。

**已有项目**：复制 `research-workflow.yaml`、`docs/` 和 `templates/`，把 `AGENTS.md` 的规则合并进原有指令而不是覆盖。英文项目用 `en/` 下的对应文件并调整指令中的路径。记录实际采用的提交版本，不只记 README 版本号。

## 运行环境要补什么

文档能规定规则，不能强制执行。下面这些需要运行环境提供：

| 控制 | 仓库已规定 | 运行环境还需支持 |
| --- | --- | --- |
| 独立核验 | 作者不能验收自己的产物 | 独立 agent 或独立审阅者；同一 agent 换角色不算 |
| 资源统计 | 汇总所有角色、重试、修正和审查成本 | token／费用遥测；缺失时只能标注估算 |
| 实时暂停 | 速率、预算、无进展等停止规则 | 持续监测、超时与取消；文档不能中断正在运行的调用 |
| 并行预算 | 启动前预留，避免重复派发与超额 | 协调者串行派发，或支持原子操作的共享预算记录 |
| 保存与恢复 | 保存成果、版本和累计用量 | 持久存储；运行中的计算能否续跑取决于实现 |
| 定期维护 | 授权、期限、累计预算与续期规则 | 调度器；复制仓库不会自动启动维护 |

缺少某项能力时，agent 应先说明，再提出替代方案（小批次、串行执行、人工检查点、独立审阅）供你批准；无法合理约束风险时不启动对应任务。

## 六个阶段

1. [定义并选择研究问题](docs/step-1.md) — 以你批准具体问题结束。
2. [方法比较与协议定稿](docs/step-2.md) — 协议批准不是实施授权。
3. [实施准备与小规模端到端验证](docs/step-3.md) — 验证通过不自动开始正式执行。
4. [正式执行与预先规定的分析](docs/step-4.md) — 负面和不确定结果如实报告。
5. [研究综合与交付定稿](docs/step-5.md) — 定稿不授权对外发布。
6. [必要交付、归档与收尾](docs/step-6.md) — 实际提交须明确授权准确版本与动作。

**模板**（`templates/`）

- 通用：项目说明、阶段契约、决策摘要、决策记录、核验报告、前序复查、证据台账（CSV）、授权记录、检查登记、启动检查、角色分配、任务分配。
- Step 1：方向记录、评估矩阵。
- 分阶段：Step 2 方法比较、有限测试、研究协议；Step 3–6 各一份计划与一份报告／交付包。
