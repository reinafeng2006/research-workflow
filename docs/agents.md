# 智能体角色与项目专长

状态：v0.9.4 新增。**这是一套未经验证的默认设计**：「按项目专长分工，比通用角色产出更多有价值的方向」这一点还没有在真实项目中测过，见第 6 节。人和 AI 谁落槌，以[人机分工](division-of-labor.md)为准。

## 1. 两层

区分智能体的是**专长**——看什么、能读什么、交出什么——而不是性格。专长改变想法的内容，性格主要改变说法。

### 固定职能：所有项目都一样

| 职能 | 做什么 | 为什么固定 |
| --- | --- | --- |
| 协调者 | 契约、分工、依赖、预算、阶段转换；四格播报 | 保持整体一致 |
| 产出者 | 生成选项、实现、执行、分析、起草，并自查 | 负责实质产出 |
| 独立核验者 | 查底层证据，逐项记 pass / fail / not_verifiable | 门槛 G2 要求它没参与过被核验的产物 |
| 质疑者 | 查假设、反例、竞争解释；**找没被任何专长覆盖的角度** | 专门唱反调，不能依赖项目恰好配了这个视角 |

这一层不随项目变，因为它存在的理由是结构性的，与领域无关。独立性规则见[共享控制](shared-controls.md)第 6 节。

### 项目专长：按项目、按阶段配置

取代原来笼统的"方法专家（按需）"。每个项目、每个阶段可以不同：Step 1 可能需要领域视角，Step 2 需要方法和统计视角，Step 5 需要目标读者视角。

## 2. 专长怎么产生

1. **推导**。AI 从两处推出专长，并写明每个专长来自哪一处：
   - 研究问题的组成：对象、结果测量、对比、边界、要支持的决定。例如"结果测量"需要测量视角，"要支持的决定"需要使用者视角。
   - [评估矩阵](../templates/appraisal-matrix.md)的敏感性：推荐最依赖哪几个分数或假设，就派专长去盯那几处。专长花在项目最不确定的地方，而不是平均分配。
2. **对照专长库查漏**。第 4 节的库逐条过一遍，每条写"需要"、"不需要"或"不需要，因为……"，防止漏掉显而易见的视角。
3. **你批准名单**。名单并入 Step 1 的「档位与可行性检查契约」授权点一起批；之后各阶段的调整在该阶段的启动授权里批。不新增授权点。
4. **数量**：每阶段 2–4 个。这是提案，按项目调整。

## 3. 每个专长写清四件事

| 项 | 例：统计与推断 |
| --- | --- |
| 看什么 | 样本量、效应量、多重比较、不确定性的表述 |
| 能读什么 | 协议、数据说明、分析计划；不读未获准查看的中间结果 |
| 交出什么 | 对每个候选方向或设计的统计风险清单，指回评估矩阵的底座条目 |
| 不能做什么 | 不替你定显著性阈值；不验收自己参与设计的分析 |

通用约束：

- 专长参与了产出，就不能独立验收同一产物——独立性规则对专长同样适用。
- 专长不改变证据规则，也不改变谁落槌。
- 方向记录里，AI 提出的方向写明是**哪个专长**提的，以便事后比较。

## 4. 专长库

这是查漏用的工作清单，**不声称完整**。推导出的专长不在库里也完全可以。

| 专长 | 主要看什么 | 常用阶段 |
| --- | --- | --- |
| 领域 | 已有工作、术语、领域惯例与公认的难点 | 1、2、5 |
| 文献与新颖性 | 问题是否已被回答、最近的邻近工作 | 1 |
| 研究设计 | 对照、偏差、混杂、可比性 | 2 |
| 测量 | 结果怎么量、效度与信度 | 1、2 |
| 统计与推断 | 样本、效应量、多重比较、不确定性 | 2、4 |
| 数据与获取 | 来源、许可、可获得性、质量、预留数据 | 1、2、3 |
| 计算与实现 | 代码、可复现性、算力与成本 | 3、4 |
| 伦理与许可 | 研究对象、知情同意、合规、潜在危害 | 1、2、6 |
| 目标读者与用途 | 谁会用这个答案、怎么用、会误读成什么 | 1、5 |
| 交付与接收方 | 格式、渠道、期限、验收要求 | 5、6 |

## 5. 人格是可选的表现层

名字、头像、口吻可以加在专长之上，用于界面体验。规则：

- 人格不改变专长的四件事。
- 界面上必须说明这些 mate 是不是同一个模型。同一个模型扮演多个角色，不算多个独立视角，"几位 mate 都同意"不是证据。
- 人格能否提高想法的多样性、或提高用户参与讨论的意愿，都**未经验证**。

## 6. 未经验证的部分

- 按专长分工是否比通用角色产出更多你愿意保留的方向。
- 按敏感性派专长是否会让 AI 只盯着已知风险、漏掉未知的。质疑者"找未覆盖角度"的职责是针对这一风险设的对策，它本身也未经验证。
- 每阶段 2–4 个是否合适。

方向记录会记下每个方向由哪个专长提出、最后是否入选。攒够几个项目就能比较；在那之前，本文按默认设计执行，不把它当成已证实的结论。
