# v0.8 小型控制案例走查

方法：对照 shared-controls.md、阶段流程图和模板，进行 14 个虚构场景的人工桌面走查。未运行真实研究、对外提交、工作 agent 或独立代理核验。下表是规则路径检查结果，不是运行时控制器测试。预算数字仅为案例，不是默认限额。

| 案例 | 输入 | 走查所得路径 |
| --- | --- | --- |
| 跨阶段授权复用 | Step 3 结果已提交，人类已批准准确的 Step 4 计划；无变化。 | 引用授权 ID，进入已批准工作；不再问同一问题。 |
| 授权增量 | 仅预算或预期产出改变。 | 保留原授权，未覆盖的增量先批准；不能用旧布尔值代替授权。 |
| 提醒不等于通过 | 有一般速率异常，批次尚未通过。 | 提醒；不进入下一批。在权限内诊断，触及停止条件即暂停。 |
| 正常推进 | 批次通过、有有效进展、无停止条件且下一批已授权。 | 预算准入满足后继续，不另加审批。 |
| 仅材料就绪收尾 | 收尾标准为 materials_ready；当前不安排提交。 | 提交授权对本次收尾不适用；如实标明未提交，由人类确认收尾。 |
| 实际提交 | 材料已准备，缺少准确版本／渠道的提交授权。 | 禁止提交；保留已准备状态。 |
| 强制要求失败 | 必要归档不可用。 | 不能改记为不适用或完成；仅不受影响部分可单独确认。 |
| 提前识别交付约束 | Step 1 已知接收方要求独立验证数据。 | 记录来源，Step 2 纳入设计；不等到 Step 6 才发现。 |
| 有效证据复用 | 准确版本、假设、依赖、用途和独立性要求仍匹配，已有通过记录。 | 引用检查 ID，仅记录适用性判断，不重跑。 |
| 局部失效 | 一个依赖发生变化，其他检查仍有效。 | 保留原记录，标记受影响依赖；只对失效部分按授权复查。失败记录不可复用为通过。 |
| 并行预算准入 | 虚构 token 单位：限额100、已用40、在途剩余30、停机预留10，新任务25。 | 合计105，拒绝启动；若新任务15则合计95，可先串行预留再启动，后续任务按更新后的余额判断。 |
| 重启与遥测 | 重启或回退；无法测量真实 token。 | 累计用量不清零；仅用获批保守估算与调用上限，无法可信约束时不启动，不宣称硬限制已执行。 |
| 角色兼任 | 协调者同时产出；原 verifier 实质修改了修复内容。 | 允许协调者产出，但其作品须其他核验者；修复作者不能独立核验该修复。 |
| 去重与暂停 | 同任务在运行，或任务已因资源异常暂停。 | 不重复派发；已有证据不能解除暂停，按获批恢复规则处理。 |

14 个场景均可按修订后的规范得到上述一致路径。实时中断、遥测准确性、无竞争的预算预留及实际核验独立性仍依赖宿主实现，本次走查未验证这些运行时能力。
