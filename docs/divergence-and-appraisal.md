# 发散与评估（Step 1）

状态：v0.9.2 新增，用于 [Step 1](step-1.md) 第 2–4 步（发散：生成方向、选择、细化）和第 6 步（评估候选）。人机分工以[人机分工](division-of-labor.md)为准：想法谁都可以提，来源要分得清，进目标要你点头。

本文的算子、扩展类、评分维度和判定阈值都是**工作清单和提案**，不是经过验证的理论。本文不声称它们穷尽了所有可能的方向，也不声称阈值已校准。

## 1. 发散：两条轴

两条轴的区别在**起点**：横向从你当前的想法出发，找别的方向；纵向从一个已经选中的方向出发，找它的下一个问题。

### 横向：八个算子

以「分步提示是否提高数学题正确率」为例：

| 算子 | 问法 | 例 |
| --- | --- | --- |
| 换对象 | 换一个人群、系统、材料还成立吗？ | 从前沿大模型换到小模型 |
| 换结果 | 换一个测量的东西会怎样？ | 从正确率换到错误类型分布 |
| 换对比 | 和别的东西比呢？ | 分步 vs 给出范例，而不是分步 vs 直接答 |
| 换尺度 | 换时间、规模或粒度？ | 从单题正确率换到整套考试的排名 |
| 换机制层级 | 从"是否有效"换到"为什么有效"，或反过来？ | 分步里是哪一步在起作用 |
| 反转假设 | 把默认前提倒过来？ | 什么情况下分步反而有害 |
| 移动边界 | 放宽或收紧范围与排除条件？ | 去掉"不含图题"的限制 |
| 换用途与受众 | 同一个现象，谁会用这个答案？ | 从评测团队换到数学教师 |

### 纵向：五类扩展

| 扩展 | 问法 |
| --- | --- |
| 上游（机制） | 为什么会这样？ |
| 下游（后果） | 所以呢？谁会因此做不同的事？ |
| 边界（失效） | 在什么条件下不成立？ |
| 推广 | 换对象或场景还成立吗？ |
| 方法重做 | 能不能用更强的设计重新回答同一个问题？ |

两条轴有重叠（"推广"和"换对象"很像）。记录时标清起点即可，不必强行区分。

## 2. 覆盖度：不数数量，逐项交代

不要求凑够多少个方向，要求**每个算子、每类扩展都有交代**：试过并产出了哪些方向；试过但没产出有用方向；或没试，以及为什么不适用。

"试过但没产出"也要记，它本身是信息：说明这个方向的空间可能已经被占满，或者问题在这条轴上不敏感。两条轴分开检查。

## 3. 实质差异

两个方向算实质不同，当且仅当下面至少一项不同：研究对象、结果测量、对比条件、能回答的决定。只改措辞或微调范围不算。

判定由 AI 提出，你确认。被判为重复的方向合并而不删除，记下并入了哪一个。

## 4. 来源与留痕

每个方向都记录在[方向记录](../templates/direction-log.md)里：

- **提出者**：你、AI，或从哪个方向派生（如"派生自 D3"）。AI 提的东西在你接受前保持"提议"状态。
- **来自哪条轴、哪个算子或扩展类**。
- **状态**：候选、入选、暂缓、淘汰。
- **淘汰或暂缓的理由**。淘汰的方向不删，下次会话才不会重新生成同样的东西，也能回头找回被错杀的方向。

攒够几个项目后，这份记录也能回答"哪些方向是谁提的、哪些最后被选中"——不预设答案。

## 5. 评估：论证底座在先，评分只用于排序

所有候选用[评估矩阵](../templates/appraisal-matrix.md)，回答**同一组问题、用同一组维度**。

### 5.1 论证底座（必填）

| ID | 问题 |
| --- | --- |
| A1 | 如果做成了，最多能说什么？ |
| A2 | 不能说什么？最常见的过度解读是什么？ |
| A3 | 依赖哪些假设？最多写三条最关键的。 |
| A4 | 这些假设不成立时会怎样？ |
| A5 | 竞争解释：还有什么也能产生同样的结果？ |
| A6 | 淘汰条件：看到什么就放弃这个方向？**事先写，不事后补。** |
| A7 | 已有工作是否已经回答过？附来源与核验级别。 |
| A8 | 与已接受目标的关系。 |

底座回答不了的那一项写"不知道"并说明缺什么，不得留空，也不得用笼统的话填满。

### 5.2 评分

七个维度，0–5 分：重要性、新颖性、可解答性、数据与权限、方法就绪度、预算匹配、伦理与风险。

**锚点**（2 和 4 介于两者之间）：

- 0：确定不行
- 1：有已知的硬障碍
- 3：没有已知障碍，但没验证过
- 5：有直接证据支持

**每个分数必须同时带两样东西，缺一样就无效、不参与排序**：

1. **指回底座**：这个分数根据底座的哪几条（如"可解答性 4 ← A1、A3"）。
2. **证据级别**：已核验、摘要级、推断、未知。

**可比性**：所有候选用同一组维度和锚点。某个维度对某个候选不适用，写明理由，不能只给部分候选打分。

**不算加权总分。**任何权重都是一个没人验证过的主张，会把取舍藏进一个数字。排序按下面的规则走，均值只作参考。

### 5.3 判定规则

按顺序检查，第一条命中即停：

| 条件 | 判定 | 意思 |
| --- | --- | --- |
| 可解答性或数据与权限 < 2 | 先降风险 | 提一个获批的小型可行性检查，别直接进设计 |
| 伦理与风险 < 2 | 先解决伦理与许可 | 投入前明确许可、使用边界与潜在危害 |
| 重要性 ＋ 新颖性 < 4 | 重新构造问题 | 回到发散，换角度而不是加预算 |
| 预算匹配 < 2 | 缩小范围或重设预算 | |
| 所有维度 ≥ 3 且均值 ≥ 3.6 | 可提交批准 | 交给你决定 |
| 以上都不命中 | 暂缓并列明未决 | 没有硬阻塞，但还不够扎实 |

这些阈值是提案。你可以改，改动记入决策记录；按改后的阈值重新判定所有候选，不只改一个。

### 5.4 敏感性

对推荐影响最大的一到三项分数或假设，写明：**如果它低两分，或这个假设不成立，判定会变成什么。**判定一碰就翻的候选，在交给你时要说出来。

## 6. 谁做什么

**AI**：按两条轴生成方向并标来源；提出实质差异判定；填底座、打分、每分指回底座并标证据级别；做敏感性；对你倾向的方向说出反对理由。

**你**：提你自己的想法；确认实质差异判定；接受或否决 AI 提的方向；选入选方向；改判定阈值；决定要不要组合。

交给你决定时，按[人机分工](division-of-labor.md)给四件套：一句话结论与建议、取决于什么、判断错了你损失什么、最少必要信息与自查位置。

## 7. 与门槛的关系

发散覆盖度（第 2 节）和评分可追溯（第 5.2 节）在模板里是必填项。它们**是否成为 G1／G2 清单项、从而能阻断就绪**，尚待你决定；在决定之前，它们不改变[门槛、档位与运行期条件](gates.md)里的计数。
