# 人工代跑对照测试（pilot）

状态：材料草稿，**尚未运行**。招募和主持由你（主持人）来做；本目录不授权任何真实用户测试。决定记录见[校准记录](../docs/calibration-decisions.md) S18-05。

## 要回答的问题

对要选题、缺专长的本科生和硕士生来说，按 Step 1 规范走一遍，是否比直接用普通 AI 聊，更能让他们得到一个**会真的去做**的研究问题？

这不是产品的效果证明。3–5 人只能看方向、发现问题，不能下统计结论。

## 设计

| 要素 | 做法 |
| --- | --- |
| 参与者 | 3–5 名有真实选题压力的本科生或硕士生（课程论文、毕业论文、RA 申请等） |
| 条件 | **S**：主持人按 Step 1 规范（精简版）带着走；**C**：参与者自己用 ChatGPT 或 Claude，不给模板、不给提示 |
| 交叉 | 每人两个条件都做；顺序轮换（一半先 S，一半先 C），用抛硬币或预先写好的顺序表决定 |
| 想法 | 每人尽量带两个不同但难度相近的想法，一个条件用一个；哪个想法进哪个条件也随机分配 |
| 时长 | 每个条件上限 40 分钟，到点停 |
| 盲评 | 一位懂该领域的老师或高年级学生，看两张统一格式的“问题卡”，不知道来自哪个条件 |
| 回访 | 一周后回访，记录是否继续推进、是否再用、是否主动推荐 |
| 付费 | 只问意愿，不收费 |

流程见 [session-script.md](session-script.md)，招募与知情说明见 [recruitment-and-consent.md](recruitment-and-consent.md)，记录表见 [record-sheets.md](record-sheets.md)。

## 预先写下的判断标准（提案，需你在第一场前批准）

主要结果：一周后，参与者是否对某个条件得到的问题采取了**可观察的行动**（发给老师、开始读文献、写进提案或申请）。

- **值得继续建**：多数参与者推进的是 S 的问题，且盲评没有明显偏向 C。
- **需要重想**：多数推进的是 C 的问题，或两边都没人推进，或参与者普遍说看不懂、不信评分。
- **看不出**：介于两者之间。这时不扩大结论，先看记录里的具体原因。

这些是事先写下的方向标准，不是统计检验。结果出来后不改标准；要改，先记一条决定再改。

## 局限（写在前面，汇报时照写）

1. **样本太小**：3–5 人，任何差异都可能是偶然。
2. **顺序与学习效应**：第二轮会受第一轮启发；轮换顺序只能抵消一部分，人数少时抵消不了。
3. **两个想法难度不可能真正相等**：差异可能来自想法本身，而不是条件。随机分配想法只能减轻，不能消除。
4. **人工代跑不等于产品**：S 条件里有一个懂规范的主持人，效果可能来自主持人而不是流程（“绿野仙踪”效应）。
5. **无法对参与者盲**：参与者知道哪个是“我们的”，可能出于礼貌偏向 S。
6. **主持人即设计者**：可能不自觉地在 S 里更用力。C 条件只读固定说明，不追加引导，以减轻这一点。
7. **盲评可能被格式泄露**：两张问题卡由主持人按同一模板整理，内容只取参与者最终选定的问题，不带分数和表格；整理过程本身仍可能泄露。盲评表最后请评审猜来源，用来检查盲法。
8. **回访是自我报告**：尽量问可核对的行动（“发给谁了”），而不是感受。

## 预算（估算）

- 每位参与者约 100 分钟：开场 10 分钟、两个条件各 40 分钟、收尾 10 分钟，另有一周后回访约 10 分钟。
- 每位盲评者每份约 15 分钟。
- S 条件的 AI 用量未测量；第一场记录实际用量后再估。
